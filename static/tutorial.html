💡 1. What is IssueMesh? (In Simple Terms)

If you work with engineering or software teams, you probably know that work gets scattered across many different websites:

  • Jira: Where project managers write plans, tasks, and feature requests.
  • GitHub: Where software developers write code, discuss pull requests (PRs), and review changes.
  • Launchpad: Where Ubuntu and open-source communities report bugs and release packages.
👁️ The Everyday Analogy: The "Messy Office"

Imagine Team A writes their notes on sticky notes on a wall (Jira). Team B works in a workshop in the basement (GitHub). Team C pins bug reports on a bulletin board in the lobby (Launchpad).

When someone asks: "Did we fix that bug, and is it ready for the customer?", you usually have to run between the wall, the basement, and the lobby, open 20 browser tabs, and try to piece together the truth. IssueMesh is like having a super-smart research assistant who reads all three boards at once and gives you the exact answer in 10 seconds.

🤖 2. Why is it Different from ChatGPT or Other Chatbots?

Many people have tried AI chatbots and noticed that they sometimes sound very confident but completely make things up (known in AI as "hallucinations").

In engineering, an invented ticket number or a fake status can cause serious mistakes. That is why IssueMesh was built with strict safety rules:

❌ Typical AI Chatbots
  • Might guess when they don't know the answer.
  • Can invent fake ticket numbers (e.g. "OPEN-9999").
  • Give vague, conversational text without real links.
  • Cannot check if a pull request was actually merged.
✅ IssueMesh
  • Zero hallucination rule: Never invents ticket numbers or statuses.
  • Always brings the receipts: Every claim links to real issues, dates, and authors.
  • Refuses to guess: If no evidence exists, it says "Insufficient evidence".
  • Spots contradictions: Warns you if Jira says "Done" but the code is still open!

🚀 3. Quick Start in 3 Easy Steps

You don't need any special technical skills to configure IssueMesh. Follow these three steps:

1

Connect Your Trackers (In Settings)

Click on the Settings tab at the top. You will see sections for GitHub, Jira, and Launchpad.

Toggle on whichever trackers you use. You can enter an API Token or Personal Access Token (PAT). Think of a token like a special digital key that allows IssueMesh to read your tickets.

🛡️ Read-Only Guarantee: IssueMesh is strictly read-only. It has no code to edit, delete, or comment on your issues. Your tickets are 100% safe.
2

Select an AI Model

In the AI Model Settings section, enter your provider's API Endpoint (for example, OpenRouter, OpenAI, or a local model like Ollama) and paste your API Key.

No typing required: IssueMesh immediately connects to the provider and fills in a convenient dropdown list of all available models. Just pick the one you like!

💡 Tip: If you don't want to use AI at all, you can still search! IssueMesh will use its built-in local search engine to find tickets and map relationships without needing any AI.
3

Ask Your First Question!

Click on the Search tab at the top. Type your question in plain English, just like you would ask a teammate, and click the orange Search button.

⚡ Watch Live: You will see a live progress box showing IssueMesh searching the trackers, following links, and assembling the evidence in real time.

❓ 4. How to Ask Questions That Work

You don't need to know fancy "prompt engineering" or special computer codes. Just ask what you want to know. Here are great examples:

  • ✔
    "What is the status of OPEN-4679 and are there any PRs open for it?"
    Great because it gives a specific ticket key. IssueMesh will find the Jira ticket, locate linked GitHub PRs, and compare their statuses.
  • ✔
    "Why is Launchpad bug 2095892 still not resolved?"
    IssueMesh will read the bug report and recent comments, then tell you who was assigned and what blocker is stopping it.
  • ✔
    "Has the Sunbeam BGP routing feature landed in code?"
    Searches across Jira epics and GitHub pull requests to verify if the code was actually merged or is still under review.
  • ✔
    "Are there any open blockers for the 2026.1 release milestone?"
    Finds release tracking issues and lists all items marked as blocking the release.
What is "Deep Search"?
Normal search engines only look for words in titles. IssueMesh performs a deep graph search: when it finds a ticket, it automatically clicks on related links, reads comments, looks up the pull requests mentioned in commit messages, and connects the whole story together for you.

📊 5. Understanding Your Search Results

When a search finishes, IssueMesh presents the information in four clean sections:

1. The Direct Answer

Evidence-Backed

A clear, concise summary (always under 250 words) answering your exact question. It highlights the current state, ownership, and key conclusions.

2. Contradiction Warnings

Important Alert

If one tracker says an issue is resolved, but another tracker shows the code is still open or unmerged, IssueMesh flags this discrepancy with an orange warning badge so you don't get blindsided.

3. Evidence Cards ("The Receipts")

Source Records

Each ticket or PR found is shown as an interactive card. You can see the ticket title, author, date, current status, and click the link to open the original ticket on GitHub, Jira, or Launchpad.

4. The Relationship Graph

Visual Map

A visual diagram showing how issues relate to each other (e.g., Ticket A blocks Ticket B, or Pull Request C fixes Bug D).

❔ 7. Frequently Asked Questions (FAQ)

Can IssueMesh accidentally edit or delete any of my tickets?
No, never! IssueMesh is engineered with compile-time, read-only guarantees. Its code physically cannot send HTTP commands like PUT, PATCH, or DELETE to your issue trackers. It can only read public or authorized information.
What does it mean when IssueMesh says "Insufficient evidence"?
Be happy when you see this! It means IssueMesh searched your trackers and couldn't find solid proof to answer the question, so it honestly told you so. Unlike typical chatbots that invent believable lies, IssueMesh prefers telling the truth about missing data.
Do I need all three trackers (Jira, GitHub, AND Launchpad) to use it?
No! You can use IssueMesh with just GitHub, just Jira, or any combination. Simply enable the ones you use in the Settings tab, and leave the others disabled.
Where is my data stored? Is it sent to the cloud?
All your search history, ticket cache, and settings are saved 100% locally on your computer in a SQLite database (inside ~/.issuemesh/). Only your search query and retrieved ticket snippets are sent to your configured AI model provider to write the summary.
What should I set the "Introspection Level" to?
We recommend setting it to None (0 / day). This keeps IssueMesh completely quiet and ensures it only uses computing resources and AI tokens when you explicitly type a search query.
